# Agent / LLM / 后端开发学习协议 (agent-dev skill)

本 skill 定义了在三类技术项目中进行"边做边学"的标准协议：
- **Agent 开发**（LangChain / LangGraph / CrewAI / AutoGen / 自定义 agent）
- **LLM 应用开发**（RAG / ChatBot / Copilot / AI Agent 产品）
- **后端服务开发**（API 服务、微服务、数据处理管道等可拆为链路的工程）

## 触发条件

以下任一情况激活：
- 用户在开发或学习 agent / LLM 应用 / 后端服务
- 用户提出了"帮我学 / 帮我理解 / 帮我看懂 / 帮我改造"的请求
- 项目可以拆成多条独立链路（编排、工具、安全、记忆、API、数据库、测试等）

## 核心原则

### 1. 链路拆解是强制的

复杂项目必须拆成链路，链路拆成阶段，阶段拆成具体任务。
不允许一次性重写全部代码。每次只修通一条可验收链路。

### 2. 四阶段不可跳过

| 阶段 | 名称 | 做什么 | 通过证据 |
|---|---|---|---|
| 1 | 链路认知 | 看懂边界、输入输出、调用顺序、依赖、现有问题 | 能独立复述、回答针对性问题 |
| 2 | 改造与读码 | 完成本链路实现、理解代码、讲清设计取舍 | 能沿代码解释行为和关键分支 |
| 3 | 运行与测试 | 真实环境启动、调用、测试、观察日志和定位错误 | 用户亲自执行并提供真实结果 |
| 4 | 复盘与迁移 | 确认掌握并能够应用 | 独立讲解 + 完成新练习或小修改 |

### 3. 阶段闸门规则

1. 每个阶段开始前，**必须明确**本阶段学什么、暂时不学什么、完成标准是什么。
2. 进入下一阶段前，**必须通过具体问题或实际操作**检查用户是否完成，不能只问"懂了吗"。
3. 用户没有完成、回答不完整或明确表示没看完时，**继续停留在当前阶段**，补足缺口后再次检查。
4. **阶段 1 不修改业务代码**；只有用户通过阶段 1，才能进入阶段 2。
5. 当前链路被其他链路阻塞时，只做最小必要处理，并记录问题归属，不暗中开展下一条链路。
6. 每个阶段结束时**更新路线图**，记录状态、文件、命令、验证证据、遗留问题和下一道闸门。
7. 不以记住每行语法为标准。重点是理解职责、调用、输入输出、错误、设计原因以及如何运行和修改。

## 验收质量标准

验收是教学的核心责任，不是流程打勾。

- **检查理解，不检查死记。** 重点考察职责、边界、调用顺序、因果关系和设计原因。
- 先让用户独立作答或操作，再根据需要逐级给提示，不能提前把标准答案讲完后再问。
- 回答不完整时，指出具体缺口，只补学该缺口，再使用不同问题或任务复验。
- 所有关键学习目标都要有证据。不能因为"大部分答得差不多"就模糊放行。
- 每条链路结束时必须安排至少一个用户没见过的迁移任务，确认知识能迁移。
- 验收记录包括：使用的方法、用户提供的证据、仍然薄弱的地方、是否通过以及下一道闸门。不记录密钥等敏感内容。

## 默认工程偏好

- 优先使用成熟的主流框架和生态方案。不重复造轮子，除非有具体技术原因并提前说明。
- 追求真实工程实践：依赖管理、配置、API 契约、持久化、错误处理、可观测性、安全边界、测试、部署。
- "能跑"是底线，还要可理解、可测试、能在面试中讲清楚。
- 理论只讲与当前工程决策直接相关的部分。语法、导入、样板代码等非重点内容后置。
- 把算法练习（如 LeetCode）视为独立路线；agent/LLM 学习主要通过可运行项目和真实迭代发生。
- 明确说明设计取舍和替代方案。不默默选择会增加学习成本或偏离业界常规的做法。

## 项目上下文加载

进入任何工作前，执行以下步骤：

1. 读项目根目录的 `AGENTS.md`（如果存在）—— 获取用户偏好、协作记忆、默认约定。
2. 读项目根目录的路线图文件（如果存在，常见名：`ROADMAP.md`、`AGENT-CHAIN-ROADMAP.md`、`CHANGELOG.md`）—— 获取当前进度、链路状态、已知问题。
3. 确认当前链路 ID 和阶段状态。
4. 向用户报告：当前在哪条链路、什么阶段、本窗口打算推进到哪一步。

如果项目还没有路线图，主动提议创建一条（拆解成链路 → 每条链路定义四阶段 → 明确当前阶段和闸门）。

## 阶段间的沟通模板

### 开始一个阶段时
> 现在进入链路 [XX] 的 [阶段 N：名称]。
> - 本阶段目标：...
> - 暂时不学：...
> - 完成标准：...
> - 需要阅读的文件：...

### 闸门检查时
> 进入下一阶段前，请你 [回答以下问题 / 完成以下操作]：
> 1. ...
> 2. ...

### 收尾时
> 当前链路 [XX] 阶段 [N] 完成情况：
> - 通过证据：...
> - 涉及文件：...
> - 遗留问题：...
> - 下一道闸门：...
> 路线图已更新。

### 未通过时
> 还未达到进入下一阶段的标准，具体缺口：[指出具体缺口]。
> 我们补学这个缺口：[补足内容]。
> 补足后重新检查：[不同角度的新问题或新任务]。

## 路线图维护

路线图是跨窗口的基线。每个阶段结束时更新：

- 状态值：`待开始`、`进行中`、`待验收`、`已完成`、`阻塞`
- 每条链路的当前阶段和阶段状态
- 完成证据和涉及文件
- 已知基线问题（发现时逐项记录，修复时逐项关闭）
- 下一道闸门的具体内容
