二、Git 到底有啥用？（核心好处）
一句话：Git 是代码 / 文档的「时光机 + 协作神器」
版本回溯：不怕改坏代码，随时可以回到任何一次提交的状态
多人协作：多个人同时写同一个项目，不会互相覆盖
分支管理：开发新功能不影响主代码，随时切换、合并
变更记录：谁改了什么、什么时候改的、为什么改，全部有记录
异地备份：把代码推到 GitHub/Gitee，不怕电脑坏了丢文件
三、手把手：用 Git 接入你的项目（入门流程）--doubao
我用最常用的「本地项目 → 提交到远程仓库」流程给你讲，照着敲就行。
1. 打开项目文件夹，进入 Git Bash
找到你的项目文件夹，右键 → Git Bash Here（装完 Git 后会多出这个选项）
会弹出一个终端窗口，路径就是你的项目文件夹，不用自己 cd 进去
2. 初始化 Git 仓库（第一次用）
bash
运行
# 初始化本地仓库，项目根目录生成 .git 隐藏文件夹
git init
3. 配置你的身份（只做一次）
bash
运行
# 设置用户名（随便起，一般用GitHub昵称）
git config --global user.name "你的名字"
# 设置邮箱（要和你GitHub/Gitee的邮箱一致）
git config --global user.email "你的邮箱@example.com"
4. 把文件加入暂存区
bash
运行
# 把所有修改的文件加入暂存区
git add .
# 或者只加单个文件：git add 文件名.py
5. 提交代码（保存版本快照）
bash
运行
# 提交暂存区的文件，并写提交说明（必须写清楚改了啥）
git commit -m "feat: 完成用户登录功能"
6. 关联远程仓库（比如 GitHub/Gitee）
先在 GitHub 上新建一个空仓库，拿到仓库地址（HTTPS/SSH）
bash
运行
# 关联远程仓库，别名 origin
git remote add origin 你的仓库地址
7. 推送到远程仓库
bash
运行
# 第一次推送，指定主分支（一般是main或master）
git push -u origin main
# 之后直接用 git push 就行
四、Gitk 怎么用？（看历史神器）
Gitk 是 Git 自带的图形化历史查看工具，非常直观。
1. 启动方法
方法 1：在项目文件夹里，右键 → Git Bash Here，输入：
bash
运行
gitk
方法 2：直接在 Windows 搜索栏输入 gitk，打开后在菜单栏选择 File → Open，选你的项目文件夹。
2. 界面怎么看
上半部分：提交历史，时间线 + 分支结构，每条线就是一个分支
下半部分：选中提交的文件变更详情，能看到具体改了哪些行
左侧：提交信息、作者、时间、哈希值，谁改了什么一目了然
3. 常用场景
想看看之前改了什么，对比不同版本的差异
排查代码是谁提交的，什么时候改的
可视化看分支合并、提交历史，比命令行 git log 直观 10 倍
五、Git 日常开发最常用的 6 条命令
记住这些，90% 的场景都能搞定：
bash
运行
# 1. 查看当前状态（哪些文件改了、哪些没提交）
git status

# 2. 拉取远程最新代码（多人协作必备）
git pull

# 3. 新建并切换到新分支
git checkout -b 新分支名

# 4. 切换到已有分支
git checkout 分支名

# 5. 合并分支（把别的分支合并到当前分支）
git merge 要合并的分支名

# 6. 查看提交历史（命令行版，Gitk 是图形版）
git log
六、补充：Git Bash vs Git GUI 日常怎么搭配用？
Git Bash：写代码、提交、推送、分支管理、解决冲突、复杂操作
Gitk：专门用来可视化看历史、分支结构，辅助理解项目变更
Git GUI：新手入门可以用，熟悉后建议主力用 Bash，因为工作里命令行是刚需
