# 如何通过拆解优秀 Agent 产品来学习 Agent 开发

> 本文记录了一次关键对话：从"找到好项目"到"怎么真正学到东西"的认知跃迁。

---

## 原问题

> 我看小红书上已经有不少人做到了类似 Claude Code 的 agent，他们应该都开源在 GitHub 上了吧？我其实想到一个问题——我看他们的成品是要学什么呢？看他的代码？看他的架构设计（设计是什么我都不知道）。我到底要通过这些好的 agent 产品去学到什么东西呢？然后通过什么去学到这个东西？不然我光找这些好的 agent，就算找到了又没啥用啊，我完全不知道自己要怎么样才能学到，而且我都不知道我自己要通过这些好的产品学到什么。

---

## 核心洞察

**不是学它的功能**（能读文件、能跑命令——这些你已经知道了）。

要学的是一套**骨架设计**——"一个 agent 拆成哪几个模块、它们之间怎么通信、数据怎么流动"。功能可以千变万化，**骨架是高度同构的**。

换句话说：**你要学的不是"它做了什么"，而是"它怎么组装的"**。

---

## 拆解框架：六个关键维度

拿着这六个问题去拆任意一个 agent 项目（OpenCode、Aider、Claude Code 等），答案就是你要学的：

### 1. Agent Loop（核心循环）

**问题**：LLM 输出 → 解析 → 执行工具 → 把结果喂回 LLM → 再输出... 这个循环怎么写？

**为什么重要**：这是 agent 的心脏。它决定了 agent 是"本能反应"还是"有规划的推理"。

**怎么找**：项目里通常是一个 `while True` 或递归调用链，找到它就能理解整个程序的主干。

### 2. Tool Registry（工具注册）

**问题**：工具是怎么注册的？注册时带了哪些元数据？调度时怎么决定哪个工具能跑、哪个不能？

**为什么重要**：这决定了 agent 的能力边界和安全性。注册机制不好，后面加工具就很痛苦。

**对比你自己**：你的 kylin-os-agent 里已经有 `ToolSpec` + `ToolRegistry` 了。对比别人的做法，看差异在哪。

### 3. Context Management（上下文管理）

**问题**：对话越来越长，token 爆了怎么办？它怎么决定丢掉哪些、保留哪些？

**为什么重要**：这是最考验工程能力的地方。不同项目策略差异很大——有截断的、有摘要压缩的、有滑动窗口的。

**对比你自己**：你当前用 SQLite 全存，没有做 token 压缩。这个缺口正是要学的重点。

### 4. Permission / Safety（权限门控）

**问题**：危险操作它怎么拦截？是 LLM 自己判断，还是代码层硬编码拦截？

**为什么重要**：这是 agent 能不能上线的关键。纯靠 LLM 自己判断"这个该不该做"是不可靠的。

**对比你自己**：你已经有多层 SafetyGuard。对比工业级做法，看深度和覆盖面差距。

### 5. Model Abstraction（模型抽象层）

**问题**：它怎么做到"换个模型不改业务代码"的？接口长什么样？

**为什么重要**：你不想被某一个模型绑死。好的抽象层让你能在 DeepSeek、Claude、GPT 之间切换，甚至本地模型。

**对比你自己**：你的 `ModelAdapter` 已经做了基础抽象，但只支持 OpenAI-compatible 格式。看看工业界怎么处理更多协议。

### 6. UI / Session（交互层）

**问题**：用户输入怎么进来、输出怎么渲染？会话怎么持久化？

**为什么重要**：agent 怎么跟人打交道，这层怎么跟核心循环解耦。解耦差了就是一团糊。

**对比你自己**：你用了 Web 前端 + FastAPI。看看 TUI 做的项目怎么处理输入输出、流式响应、实时渲染。

## 怎么学——操作方法

**不是**"把代码从头到尾读一遍"。

**而是**"带着问题去找答案"：

| 步骤 | 操作 | 你要找到什么 |
|---|---|---|
| 第 1 步 | 找 main loop | 一个 while/递归调用，LLM 输出后怎么分支（结束 or 调工具） |
| 第 2 步 | 找工具定义 | 工具注册代码，注册时传了什么参数 |
| 第 3 步 | 搜关键词 "context" "token" "truncat" "summariz" | 上下文管理策略 |
| 第 4 步 | 搜关键词 "permission" "confirm" "deny" "sandbox" | 权限门控代码 |
| 第 5 步 | 搜关键词 "model" "provider" "client" | 模型抽象层 |
| 第 6 步 | 搜关键词 "session" "history" "persist" | 持久化代码 |

**你不需要读完所有代码**。每个项目可能只需要读 5-10 个关键文件，每个文件读 50-100 行就能拿到答案。

## 最终输出：架构对比表

不是"我读完了"——而是**一张对比表**：

| 维度 | kylin-os-agent（当前） | OpenCode | Aider | Claude Code |
|---|---|---|---|---|
| **Agent Loop** | `orchestrator.handle()` 单次循环 | 待拆解 | 待拆解 | 多步递归 |
| **Tool Registry** | `ToolSpec` 注册表，带 risk/permission/mode | 待拆解 | 待拆解 | 大型工具集 |
| **Context** | 未做压缩（SQLite 全存） | 待拆解 | 待拆解 | 自动压缩 |
| **Permission** | SafetyGuard 多层硬编码 | 待拆解 | 待拆解 | 确认+沙盒 |
| **Model** | OpenAI-compatible 单接口 | 待拆解 | 待拆解 | 多 Provider |
| **UI** | Web 前端 + FastAPI | TUI | 终端 diff | TUI + IDE |

这张表填完，你就**真正看懂了**，不是"看过"。

## 推荐拆解顺序

| 顺序 | 项目 | 理由 |
|---|---|---|
| 1 | **Aider** | Python 写的，代码最简洁，一个 repo 就能看完核心逻辑。适合入门 |
| 2 | **OpenCode** | 架构最完整（最接近 Claude Code），有 sub-agents、TUI、session 管理。适合进阶 |
| 3 | **Claude Code**（部分开源） | 看它是怎么把上面那些维度做到极致的。作为标杆对照 |

---

> **核心心法**：
> 你想学的不是"怎么写 agent"（API 调用谁都会），
> 而是"怎么设计一个能长大的 agent"（骨架好，加功能才不痛苦）。
> 这就是为什么重点看架构而不是看功能。
